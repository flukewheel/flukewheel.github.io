# Phase 2 hosted backend and avatar processing

Submitted: 29 October 2026 at 16:34 Europe/London

## Added

- Created a separate `flukewheel-dev` Supabase project in the connected `subanglo.tv` organization, London region. The quoted project cost was $0 monthly and the user confirmed it.
- Applied the reviewed foundation and avatar security migrations to the hosted project, with matching migration versions in the local monorepo.
- Deployed the import smoke and authenticated avatar processing Edge Functions.
- Added a trusted avatar processor that checks the actual image format and decoded dimensions, bounds upload size, auto-orients, resizes, re-encodes WebP, stores under the verified user's path and updates the profile.
- Removed direct client writes to avatar storage and profile avatar paths.
- Added a local authenticated upload integration check and hosted development setup notes. Saved only the hosted publishable key in an ignored local environment reference.

## Verified

- A clean local database reset applied both migrations and the local seed.
- The SQL security suite passed, including direct-write denial and owner-only avatar reads.
- Local security and performance advisors reported no warnings.
- The local avatar runtime accepted a real PNG, updated the profile and rejected malformed and oversized uploads.
- The hosted import smoke function returned the expected request ID. The hosted avatar function rejected an unauthenticated request.
- Hosted inspection found twelve RLS-enabled application tables, two media buckets, no client avatar-path write grants and no avatar storage write policies.
- The existing lint, typecheck, unit tests and build passed after the repository changes.
