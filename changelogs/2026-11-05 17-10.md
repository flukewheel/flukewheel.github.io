# Phase 6 Bump selection and viewer implementation

Submitted: 5 November 2026

Replaced browser-side full-catalogue Bump selection with bounded PostgreSQL candidate selection and a guest-capable Edge Function. Added category affinity, a 75/25 preference/exploration starting mix, recency relaxation, strict category boundaries, member history and idempotent retries. Recommendation ranking now uses the same eligible pool and activity signals. The browser keeps 20 recent IDs, ignores stale Bump results, explains empty pools and repeats, and copies the original website URL. The viewer displays title/domain and delayed loading guidance without changing the owner's viewer-only policy.

Both migrations and the Edge Function are deployed to hosted Supabase. A hosted guest request returned an eligible site. A clean local reset, role-scoped SQL tests, member retry test, lint, typecheck, unit tests and build passed. The first full browser run passed 42/42 journeys; the later 46-test run passed 45/46, and its one existing mobile reaction failure passed on an isolated rerun. The hosted security advisor showed only its existing leaked-password-protection warning. The Pages frontend release and live viewer review remain to be completed.
