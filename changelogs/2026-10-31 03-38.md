# Phase 3 email callback and recovery repair

Submitted: 31 October 2026

The project owner reported that a hosted email confirmation returned to home without a username prompt, and that the password-reset prompt reappeared when bookmarking after a successful reset.

## Changed

- Process authentication returns before creating the hash router, so token fragments are not mistaken for routes.
- Accept both PKCE code callbacks and email token fragments, removing credentials from the URL before rendering.
- Save the intended viewer route in bounded browser storage as well as tab storage, so a confirmation opened in another tab of the same browser can restore it.
- Close the password dialog and leave recovery mode after a successful password update.
- Added browser checks for cross-tab confirmation-style returns and bookmarking after recovery.

## Verification

Lint, typecheck, six unit tests, the production build, and all 30 desktop/mobile browser checks passed. The hosted email confirmation still needs an account-owner retest after deployment.
