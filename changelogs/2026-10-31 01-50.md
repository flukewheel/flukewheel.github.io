# Viewer-only website navigation

Submitted: 31 October 2026

The project owner decided that active catalogue websites must always be attempted directly inside the Flukewheel viewer. The browser's own error or empty frame is preferred when a third-party site refuses embedding. This supersedes the earlier external-opening fallback in `plan.docx`.

## Changed

- Removed the "A discovery to open" screen and its Open original website button.
- Removed the toolbar action that opened the original website in a new tab.
- Kept all active catalogue entries discoverable. Embedding status remains stored for curation but no longer controls viewer rendering.
- Updated both catalogue batch comments and current architecture notes to reflect the viewer-only behaviour.

## Verified

- A previously blocked entry now mounts an iframe with its original URL and shows no external-opening control. The homepage still mounts no iframe.
- Web lint, typecheck, six unit tests, production build, and all 28 desktop/mobile browser tests passed.
