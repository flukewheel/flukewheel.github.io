# Phase 8 testing and hardening progress

Phase 8 is in progress. This phase covers the complete MVP, including access boundaries, abuse controls, accessibility, performance and privacy. The completion check in `plan.docx` requires critical journeys to pass, no high-impact access issue to remain, a fresh database reset to succeed and errors to let visitors continue.

## Completed so far

- Inventoried the existing Vitest, React Testing Library, Playwright and SQL checks. Phase 7 ended with a clean migration reset, 62 passing browser journeys and published signed-in checks.
- Added `tests/integration/phase8-access-boundaries.mjs`. It creates disposable users A/B and an administrator in the local Supabase stack, then calls REST/RPC/Storage as those users and a guest. It checks pending catalogue visibility, profile/bookmark/history isolation, cross-account writes, owner reassignment, private role access, trusted administrator RPC access and guest/member recommendations. Storage checks cover private avatar owner reads, cross-account and guest denial, public thumbnail reads and browser-role upload denial. The check passed, and all test accounts, images and the pending website were removed.
- Added `scripts/check-public-bundle.mjs` and a predeploy Pages workflow step. The current built text assets passed; a synthetic Supabase secret key was rejected. The check reports file and credential type without printing the credential.
- Added a Postgres-enforced, atomic per-minute quota at the direct Bump and recommendation RPC boundaries. Verified JWT member IDs receive separate allowances (60 Bump and 90 recommendation calls per minute). Anonymous Bump calls share a 600-per-minute global allowance because a trustworthy platform IP header has not been established. Client-provided forwarding headers are not treated as identity. The table has no anonymous/member access and old rows are removed by a daily job. Edge Bump returns HTTP 429 with `Retry-After`, and the app shows a retry message for both paths.
- `supabase/tests/phase8_discovery_quotas.sql` passed against the local database with a rollback. It checked the actual RPC boundaries, member separation, anonymous cap and anonymous recommendation denial. The Phase 8 direct REST/RPC access test, typecheck, lint, Vitest, production build and public bundle credential check also passed after this change. An early two-worker Playwright run had desktop timing failures; the runner now uses one worker and the expanded full suite passed 70/70.
- A separate temporary Supabase project on distinct ports completed a fresh database reset through the Phase 8 migration and both seed files. The quota SQL check passed against that fresh database. Its containers, data volume and copied files were removed; the working local database was not reset.
- The Phase 8 migration was pushed to the linked hosted database, the updated `bump-website` Edge Function was deployed, and a hosted guest Bump request returned HTTP 200 with a website ID. GitHub Pages run [42433929337](https://github.com/flukewheel/flukewheel.github.io/actions/runs/42433929337) completed successfully for commit `87e05d3`.
- Expanded the local API check to run guest suggestion, administrator queue and approval, then confirm public visibility and clean up. It also rejects a chunked administrator request above 8 KiB. Obfuscated IPv4 and IPv6 URL rejection cases pass. A pattern scan of the added lines in 63 Git commits found no secret-key or service-role JWT patterns. Details and remaining trust assumptions are in [the Phase 8 security review](phase-8-security-review.md).
- Added a Pages-compatible production meta CSP, bounded administrator bodies regardless of `Content-Length`, and removed decoder detail from avatar error logs. Production-preview home and Wheel journeys at desktop/mobile widths and a hosted-configuration preview produced no CSP violations. Header-only controls such as `frame-ancestors` are unavailable through this meta policy.
- Added Phase 8 browser checks for focus trapping/restoration, Escape, rate-limit retry, 320 px reflow and reduced motion. Fixed narrow tooltip overflow, input/textarea focus outlines and low-contrast reaction error text. The full production-preview Playwright suite passed **70/70** desktop and mobile journeys with one worker. Typecheck, lint, Vitest, build and bundle-secret scan passed.
- The documented Pixel 7 profile (4× CPU, 1.6 Mbps down, 0.75 Mbps up, 150 ms latency) measured homepage LCP p75 at **2.408 s local** and **2.476 s published** across five cold contexts each; measured CLS was **0**. One published LCP sample was 5.196 s, so the tail still warrants monitoring. Twenty-five hosted guest Bump requests after two warmups measured **444 ms p95** (152 ms median); these are endpoint times, excluding any external iframe load.
- Recorded data use, browser storage, deletion/export behavior, external-site behavior, retention gaps and owner decisions in [the Phase 8 technical privacy review](phase-8-privacy-review.md). A one-site guest cookie sample found no cookies in that Chromium context but did observe an external-site request. Published Google OAuth initiation reached `accounts.google.com`; a real account sign-in remains an owner check.
- The final hardening commit `e61159b` published through Pages run [42447672008](https://github.com/flukewheel/flukewheel.github.io/actions/runs/42447672008). Hosted `admin-catalogue` and `process-avatar` both returned HTTP 401 to unauthenticated requests. Headless desktop/mobile checks found the published CSP and completed home and Wheel discovery without browser errors. The final published mobile profile measured **2.180 s LCP p75** and **0 CLS** across five cold contexts. The remaining owner steps are in [Phase 8 owner checks](phase-8-owner-checks.md).

## Next work against the plan

- **8.1 Boundaries and journeys:** The production-preview suite passed 70/70 and published guest home/Wheel smoke checks passed. A fresh isolated database reset already passed the Phase 8 migration; subsequent changes do not add migrations. A real Google account sign-in on the published origin still needs owner confirmation.
- **8.2 Security and abuse:** Replace the pooled guest cap with a short-lived salted identifier only after a platform IP source can be verified; the shared cap currently permits one caller to exhaust the guest allowance for everyone. External destinations remain a manual browser-review boundary because the server does not fetch them. A future host with response-header control could add `frame-ancestors` and CSP reporting.
- **8.3 Accessibility, performance and privacy:** Keep measuring performance tails. The 320 CSS-pixel reflow check covers the layout width corresponding to 400% zoom on a 1280-pixel viewport, though automated Chromium keyboard zoom did not change the headless browser's zoom level. The owner must set retention periods, controller/contact and lawful-basis details, and decide the cookie audit and consent approach for embedded sites before publishing a final privacy notice.
